Query the whole player pool.

Data: FIFA Women's World Cup, 2019 — StatsBomb competition 72, season 30.
Course reading: Soccermatics Lesson 3 — Case study: spreadsheet scouting.
Technical reading: SQLite → Window functions → PARTITION BY and DENSE_RANK. Our SQL implementation is a custom course extension.

We have finished a combined report. Now we build a reusable tool: a database where you can ask the same question about all 35 fullback profiles.

What we built

  • fullbacks: 35 rows. One row represents one player/team profile for this competition and season.
  • qualifying_fixtures: 145 rows. One row represents one player's included match, not an additional player or a unique tournament match.
  • fullback_metrics: a SQL view that calculates rates from counts and registered playing time.

Names are labels; compound IDs identify records. The fixture table references the player table with a foreign key. The original passing, forward-pass and pressure definitions remain unchanged.

The first reusable question

Among the right-sided profiles in our existing pool, who recorded the most completed eligible passes per 90?

The query returns 14 profiles. Bronze has 45.57 completed passes/90 and is first for this activity measure in that group. This does not establish that she is the best fullback.

New SQL: rank within a group

DENSE_RANK() OVER (
    PARTITION BY side_group
    ORDER BY completed_per90 DESC
)
  1. PARTITION BY side_group: compare left, right and mixed-side profiles in separate groups.
  2. ORDER BY ... DESC: put larger activity values first.
  3. DENSE_RANK: assign ranks while keeping ties equal.
Values: 10, 10, 8
Ranks:   1,  1, 2

A window function keeps each player's row. GROUP BY would normally collapse rows into summaries. This rank is also different from the percentile convention we used earlier.

Use it in Spyder or the terminal

Run 81_scouting_database.py in Spyder to rebuild the database and print the default queries. In the terminal, from your project directory:

python 81_scouting_database.py --side right_only --min-starts 3

The database is saved at /Users/alireza/football-analytics/data/local/81_scouting.sqlite3. SQL source: schema and role/activity query. Python includes SQLite, so no new database server is needed.

Keep the comparison population explicit

There are 17 exclusive left-side, 14 exclusive right-side and four mixed-side profiles. These labels describe qualifying starting roles, not every minute or the player's entire career. A higher minimum-start filter narrows the existing pool before ranks are calculated. It does not recover players excluded from the original three-start cohort.

Practice: values are 20, 20, 15, 10. What ranks does DENSE_RANK produce?

1, 1, 2, 3. The first two values tie; the next distinct value receives rank 2. This is an order of the chosen metric, not an overall quality score.
