Connect a corner to its shots.

We now have two tables: 45 corner records and 21 phase-shot records. A join connects them using match ID and corner ID.

One corner can match several shots

Corner A → Shot 1
Corner A → Shot 2
Corner B → no matching shot

The joined result has three rows, but there are only two corners. The same corner repeats for each matching shot.

Completed assignment

Our real left join returns 47 rows. The original corner table still contains 45 deliveries. We grouped shots per corner before the final join and reproduced the correct 19/45 shot-association rate.

Before counting a joined result, ask: what does one row represent now?

Read the connection

FROM corners AS c
LEFT JOIN phase_shots AS s
  ON c.match_id = s.match_id
 AND c.corner_id = s.corner_id

LEFT JOIN keeps corners even without a matched shot. ON gives the matching keys. c and s are short table names used in this query.
